# 01 · 能力分级清单

## 等级定义

| 等级 | 含义 | 过关标准 | 条数 | 工时 |
|---|---|---|---|---|
| L1 肌肉记忆 | 写游戏时的基本功，必须条件反射 | **闭眼从零重写** | 18 | ~42h |
| L2 系统搭建 | 中型项目的骨架，必须能独立搭 | **不看教程从零搭出** | 26 | ~108h |
| L3 深水区 | 拉开水平差距的部分，**校招面试高频区** | **能讲清原理 + 能定位问题** | 10（求职向必做 4 条 + 选修）| ~63h |

**【白板重写】** 本文件反复出现这个词，定义如下：
关掉 Unity、关掉教程和文档、开一个空文件，只看自己的记忆把核心模块写出来。
写不出来就是没学会，不算过关。这是整份计划里唯一有效的验收手段。

## 校招考频对照（求职向必读）

| 考频 | 条目 | 说明 |
|---|---|---|
| 极高（必须能讲 10 分钟）| L2-01 对象池、L2-02 事件系统、L2-04 状态机、L3-01 Profiler | 这四项几乎是 Unity 客户端岗的必问题，而且你的项目里必须有真实数据 |
| 高 | L1-01 至 L1-05（物理与输入）、L2-06 SO 配置、L2-07 存档、L2-09 场景管理、L2-10 Addressables、L3-02 批处理、L3-03 GC | 二面常见 |
| 中 | L2-11 UI 框架、L2-14 伤害链、L2-19 音频、L2-24 异步、L3-04 物理性能 | 看面试官方向 |
| 低 | L1-07 至 L1-11（动画与 UI 细节）、L2-12 背包、L2-15 Buff、L2-17 波次曲线 | 做项目要用，但面试很少专门问 |

**结论：求职向的 L3 必做项是 L3-01 / 02 / 03 / 04（性能优化四件套）。**
这不是「深水区选修」，这是面试送分区。L3-05 之后的 Shader、编辑器扩展、网络按目标公司挑 1-2 条即可。

## 阶段 0 · 工具链地基（约 6h）

> 原清单完全没有这一块，但它是所有后续工作的地基。
> 没有它，你不敢重构代码，也就不可能学会架构——因为你怕改坏了回不去。

| 编号 | 练什么 | 产出物 | 验收标准 | 预估 |
|---|---|---|---|---|
| S-01 | 版本控制 | Unity 专用 .gitignore（忽略 Library/Temp/Logs/obj/Build）；项目设置为 Force Text 序列化；装好 Git LFS 管大文件 | 能独立完成「改代码 → 提交 → 改坏 → 回滚到上一版」全流程；能说出 .meta 文件为什么必须入库 | 2h |
| S-02 | 项目规范 | 一套固定目录结构（Assets/_Project 下分 Scripts / Prefabs / Art / Audio / Scenes / Data）；一个可复制的项目模板 | 新项目 10 分钟建好骨架；能说出代码放 Assets 根目录的坏处 | 1h |
| S-03 | 新输入系统 | New Input System 接入；一个 Input Actions 资产（移动/跳跃/攻击/暂停，含键鼠和手柄两套绑定）；一层输入封装 | 不做任何改动就能从键鼠切到手柄；业务代码里不出现任何 Input.GetXxx | 2h |
| S-04 | 调试能力 | Rider 或 VS 断点调试打通；Console 日志规范（分级 + 条件编译）；附加到 Unity 进程 | 能在一个正在运行的 Unity 里断点停住并查看变量；能说出 Debug.Log 在正式构建里的处理方式 | 1h |

**阶段出口**：能建一个空项目，写个方块，提交，改坏，回滚，整个过程不用查教程。

## L2 · 系统搭建（26 条，约 108h）

> 这一层全是「做中型项目必须自己搭一次」的东西。
> 每一项都必须是**自己先写一版能跑的**，然后才允许去看官方实现或开源项目做对比。

| 编号 | 练什么 | 产出物 | 验收标准 | 预估 |
|---|---|---|---|---|
| L2-01 | 对象池 | 自写通用泛型 Pool，把子弹、敌人、飘字、特效全部迁过去，并做出 Profiler 前后对比截图 | 白板重写；能说出池子容量的取舍；能说出池对象复用时最容易出的三类坑（残留协程、残留事件订阅、残留物理速度）| 5h |
| L2-02 | 事件系统 | 泛型事件总线 + 明确的订阅/退订生命周期 + 至少让 3 个系统之间不再直接引用 | 能说出事件和直接引用的取舍边界；知道订阅泄漏怎么产生、怎么在 OnDisable 里防 | 4h |
| L2-03 | 管理器与初始化顺序 | 单例基类 + GameManager + DontDestroyOnLoad + 明确的启动顺序 | 能说出单例的坏处和替代方案（服务定位器 / DI）；能处理「场景重载后管理器重复」这个经典坑 | 3h |

| L2-09 | 场景管理 | 主菜单 → 加载 → 游戏 → 结算 全流程；异步加载进度条；用 Additive 让 UI 场景常驻 | 能说出 DontDestroyOnLoad 和 Additive 各自的取舍；能解释进度条为什么会卡在 0.9 | 5h |

## L3 · 深水区（10 条，选修 3-5 条，约 63h）

> 这一层决定你和「会做 demo 的人」之间的距离。
> **求职向必做 L3-01 / 02 / 03 / 04（性能优化四件套）。** 这几乎是一面必问的内容，而且必须有真实数据支撑。
