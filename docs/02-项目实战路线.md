# 02 · 项目实战路线（校招求职版）

## 和「学会做游戏」版本的三处改动

| 原设计 | 求职版 | 为什么 |
|---|---|---|
| 项目 A / B / C 三个完整项目 | 项目 A 压缩成 3 周热身；**项目 B 升格为主谈资**；项目 C 换成技术专项 Demo | 面试只讲得动 1-2 个项目，做三个半成品不如做透一个 |
| 追求「完整的游戏」 | 追求「**有 6 个能讲 10 分钟的技术点 + 真实数据**」 | 面试官不关心好不好玩，关心你怎么解决问题 |
| 无 | 新增「已有作品叙述化」 | 你的 Game Jam / 上线作品是现成资产，改造比重做便宜得多 |

**总原则：作品不是做给玩家看的，是做给面试官看的。**
每做完一个功能，问自己一句：**「这个能成为面试谈资吗？」** 答不上来的，要么补技术含量，要么砍。

## 项目 A · 2D 平台跳跃（3 周热身，不是主线）

### 为什么还要做
不是因为它重要，而是因为它能在 3 周内让你摸清两件事：
① 你的 L1 基本功还剩多少；② 你现在的项目节奏是快是慢。**摸完底就立刻停手。**

### 压缩后的范围（只做三个里程碑，不许加）

**M1 · 玩家控制器（1 周）**
- [ ] 新输入系统 + Rigidbody2D 在 FixedUpdate 里改 velocity
- [ ] 跳跃：可变高度 + 土狼时间 + 跳跃缓冲 + 落地检测
- [ ] 摄像机跟随 + 边界
- **禁查时刻**：手感调参阶段禁止抄任何教程的数值，自己一格一格调

**M2 · 关卡与敌人（1 周）**
- [ ] Tilemap 搭 2 关
- [ ] 1 种敌人（巡逻 + 接触伤害，走 IDamageable 接口）
- [ ] 收集品 + 计分

**M3 · 收尾（1 周）**
- [ ] 主菜单 → 游戏 → 死亡重开
- [ ] 完整玩一遍，录 30 秒，写复盘
- [ ] **立刻停手，不要加功能**

### 这个项目能贡献的谈资（准备 2 个就够）
1. **手感调参的方法论**：土狼时间和跳跃缓冲各自解决玩家的什么心理预期？为什么这两个参数比跳跃高度更影响手感？
2. **接口解耦**：为什么伤害走 IDamageable 而不是直接改血量？接入新敌人时已有文件改了几个？
3. （加分）**帧率无关插值**：为什么直接写 Lerp 在 144fps 和 60fps 下表现不同？

## 项目 B · 俯视角射击（9-12 周，主作品）★ 这是你的核心资产

> 这个项目的一切设计都服务于一个目的：
> **让你在面试里能连续讲 20 分钟而不重复、不含糊、不露怯。**

### 范围硬约束

- 1 张有限地图（墙 + 掩体）
- 3 种敌人（近战冲脸 / 远程射击 / 自爆）
- 2 种武器，可切换
- 波次递增 + 难度曲线（走 SO 配置）
- 掉落系统 + 最高分存档
- 暂停 + 设置（音量、灵敏度）

**美术一律用占位方块。** 时间花在系统上，不花在美术上。

### 里程碑与「必须产出的技术谈资」

| 里程碑 | 时长 | 做什么 | 必须产出的谈资（含数据）|
|---|---|---|---|
| M1 核心循环 | 1.5 周 | 移动、瞄准、射击、受击、血条、分数 | 先用最笨的 Instantiate 实现，**故意留下性能问题**，作为后面优化的对照基线 |
| M2 对象池 | 1.5 周 | **手写**通用泛型 Pool，子弹/敌人/飘字/特效全部迁过去 | ★1：Profiler 前后对比截图。GC Alloc 从每帧 X KB 降到 ~0；说明池对象复用要重置哪三类残留状态 |
| M3 事件系统 + UI | 1.5 周 | **手写**事件总线；UI 只订阅不引用；面板基类 + 面板栈 | ★2：删掉 UI 场景，核心逻辑照样跑不报错；说明事件与直接引用的取舍边界、订阅泄漏怎么防 |
| M4 敌人 AI | 2 周 | **手写**状态机框架 + 3 种敌人 + 波次生成器 + 难度曲线 | ★3：新增第 4 种敌人时已有文件改动数为 1（只有配置）；说明可扩展性来自哪里 |
| M5 深度系统 | 1.5 周 | 掉落表（权重 + 稀有度 + 保底）、武器策略模式、Buff 装饰器 | 谈资：1000 次掉落的分布统计，验证符合设计 |
| M6 数据与持久化 | 1.5 周 | SO 配置（敌人/武器/波次）、存档（带版本号 + 迁移）、音频池 + AudioMixer | 谈资：删掉存档文件后游戏正常从默认值启动；老版本存档能被新版本读 |
| M7 性能优化专项 | 1.5 周 | 拿 M2 留下的基线做全面优化 | ★4：完整性能报告。帧率从 A 到 B；DrawCall 从 X 到 Y（图集 + SRP Batcher + GPU Instancing）；内存峰值变化 |
| M8 收尾 | 1 周 | 打击感四件套（震屏/顿帧/粒子/音效）、构建、演示视频、项目 README | 完整构建包 + 3 分钟演示视频 + 能给面试官看的 README |

**★ 标记的 4 个谈资是硬性交付物。** 每个都要能：
- 讲 5 分钟不卡壳
- 往下钻 3 层（例如对象池 → 泛型怎么设计 → 池对象残留状态有哪些 → 为什么用 Queue 而不是 Stack）
- 给出一个数字

### 自检问题（面试官会问的原型）
- 对象池复用时容易残留哪几类状态？漏掉哪个会出什么 bug？
- 事件系统和直接引用，你在哪些地方选了哪个？为什么？
- 新增一种敌人需要动几个文件？如果超过 2 个，说明哪里没解耦好？
- 你的难度曲线是怎么设计的？为什么不是线性递增？
- 存档版本迁移怎么做的？如果玩家跨了两个版本更新会怎样？
- 你现在项目里最大的性能瓶颈是什么？你怎么找到它的？

## 技术专项 Demo（4 周，三选一）

> 主作品 B 是「系统集成能力」，专项 Demo 是「**某个方向上的深度**」。
> 面试官问「你除了做游戏还会什么」，答案在这里。

| 方案 | 做什么 | 展示什么能力 | 适合 |
|---|---|---|---|
| **A 案 · 编辑器工具** | 批量资源检查工具（找缺失引用/未赋值字段）+ 一键打包脚本 + 自定义 EditorWindow | 工程化、工具链、Editor 编程 | 投中厂、工程向团队 |
| **B 案 · 渲染与效果** | 描边 / 溶解 / 顶点动画 + 后处理调优 + 一份效果对比 | Shader 与画面表现 | 投美术向、独立向团队 |
| **C 案 · 系统深挖** | 自己实现一个协程调度器，或一个极简 ECS，或一套帧同步 Demo | 引擎原理理解、抽象能力 | 投大厂提前批、引擎向团队 |

**推荐（按你的画像：中厂标准向下兼容）**：优先 **A 案**。
理由：Editor 工具是所有团队每天都缺的东西，而且它天然是「你自己想到并解决的痛点」，讲起来最有说服力。
B 案次之。C 案风险最高 —— 讲不好容易露怯，除非你确实想冲引擎方向。

**交付物（不管选哪个）**：
- 一个能开源出去的完整小项目（可直接给面试官看代码）
- 一份说明文档：为什么做它、解决什么问题、怎么用、遇到什么坑
- 一段录屏演示

## 已有作品叙述化（1 周）

你的 Game Jam / 上线作品是**现成资产**，但大概率处于「能玩，但说不出技术含量」的状态。花一周改造它：

- [ ] 补一份像样的 README：做什么、怎么玩、技术栈、我负责哪部分
- [ ] 找出 3 个当时的技术决策，写成「问题 → 方案 → 取舍」
- [ ] 补数据：哪怕只是「把加载时间从 8 秒降到 1.2 秒」这种粗糙的统计
- [ ] 准备 3 个故事：最难的一个 bug、最有争议的一次设计分歧、如果重做会改什么
- [ ] 清理代码仓库：目录、命名、死代码、commit 信息

> **Game Jam 作品的价值不在「完整」，而在「时间压力下的取舍」。**
> 面试官很吃这一套：「48 小时里我砍掉了联机功能，保住了核心循环」比「我做了十个功能」值钱得多。

---

## 求职版项目纪律

1. **对象池、事件系统、状态机必须手写。** 用插件等于放弃面试送分题。
2. **先故意写丑，再优化，留下对照数据。** 一上手就写最优解，你反而没有故事可讲。
3. **每个功能做完立刻问：这能成为谈资吗？**
4. **每个技术点必须有数字。** 没有数字的技术点等于没有。
5. **项目代码仓库必须能见人。** 每天提交，commit 信息写清做了什么、为什么。
6. **不许在冲刺期（W21 之后）开新项目。** 只整理、只打磨、只复盘。
7. **每个项目都必须真的打一个构建包给别人玩。** 从「我电脑上能跑」到「别人电脑上能跑」的坑，面试会问。
