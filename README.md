### 这份计划最重要的一句话

校招挂在 Unity 客户端岗上的人，**极少是因为"没有作品"**，绝大多数是因为这三件事：

1. **有作品但讲不出来** —— 面试官问「你这个对象池怎么设计的」，你只能答「就……存起来复用」
2. **笔试算法过不了** —— 一道中等难度题写不出来，简历再漂亮也进不了面
3. **八股只背不理解** —— 背得出"协程不是线程"，但答不出"那协程到底怎么执行的"

所以这份计划的重心不是「再做几个游戏」，而是：

**把已有的作品变成技术故事 + 补上算法与引擎原理 + 练表达。**

## 1. 求职版和「学会做游戏」的根本区别

| | 学会做游戏 | 校招求职 |
|---|---|---|
| 目标 | 做出好玩的游戏 | 通过笔试面试 + 有能讲 20 分钟的作品 |
| 重心 | 广度与实现 | **深度 + 原理 + 表达** |
| 项目数量 | 越多越好 | **1 个主讲作品 + 1 个技术专项 + 已有作品** |
| 判断标准 | 好玩不好玩 | **能不能被追问 3 层还不露怯** |
| 额外要求 | 无 | 算法、八股、手撕代码、简历、讲述、投递节奏 |

**结论：原来那份「194 条刷完」的路线对求职是低效的。** 你不需要会用 194 个 API，你需要的是 8 个能讲 10 分钟的技术点。

## 2. 三条并行线（求职版的核心结构）

求职准备必须三条线同时跑，任何一条断了都会在某个环节挂掉。

| 线 | 投入 | 内容 | 断掉的后果 |
|---|---|---|---|
| **作品线** | 每周 10h | 走 02 号文件的项目路线，产出 2 个作品 + 1 个专项 Demo | 面试没得聊 |
| **原理线** | 每天 40min | 走 05 号文件的八股清单（C# 基础 + Unity 引擎原理）| 二面必挂 |
| **算法线** | 每天 1-2 题 | 走 05 号文件的手撕与算法清单 | 笔试挂，简历都递不进去 |

合计约 **17 小时/周**。如果每周只有 10 小时：**保住原理线和算法线，作品线砍到只做项目 B。**

## 5. 求职版八条红线

破了任何一条，前面的努力都会在某个环节打折。

1. **对象池、事件系统、状态机必须手写。** 不许用现成插件。面试问的就是这三个，用插件等于放弃送分题。
2. **每个功能做完立刻问：这能成为面试谈资吗？** 答不上来的功能，要么补技术含量，要么砍掉。
3. **每个技术点必须有数字。** 「优化了性能」是废话，「GC Alloc 从每帧 2.4KB 降到 0」才是谈资。没有数字的技术点等于没有。
4. **简历上出现的每个词，都要能被追问 3 层。** 写了 Addressables 就要能答出「和 Resources / AB 的区别」以及「句柄什么时候释放」。
5. **每天至少一题算法，中断不超过 3 天。** 手感会掉，掉了要两周才回来。
6. **每周一次模拟面试。** 对着摄像头讲 5 分钟自己的项目，录下来自己看。你会发现自己讲得多烂——这是好事，早发现。
7. **投递前代码仓库必须是「能给面试官看」的状态。** README、目录结构、commit 历史、运行说明。面试官真的会点进去看。
8. **投递期不许学新东西。** 投递期只做两件事：复盘每场面试 + 补被问到但不会的漏。
